Factory Inventory Management System

Architecture overview — Vue 3 SPA + FastAPI + in-memory JSON data store

System Architecture

Three-tier separation: browser-side SPA talks to a stateless REST API, which serves data loaded once at startup from JSON files. No database, no auth — built for demo and workshop use.

Data Flow

A single user filter change propagates through six steps. Reactivity is driven by Vue refs/computed; the server is stateless.

1
User toggles a filter in FilterBar.vue
Updates shared refs in composables/useFilters.js (warehouse / category / status / month).
2
View component watches filter refs & calls api client
e.g. Dashboard.vue calls api.getDashboardSummary(filters).
3
client/src/api.js serializes filters to query params
Skips any filter equal to 'all'; uses axios to GET http://localhost:8001/api/….
4
FastAPI applies in-memory filters
apply_filters() (warehouse/category/status) and filter_by_month() (month string or quarter Q1-2025…Q4-2025) over already-loaded lists.
5
Pydantic models validate the response
InventoryItem, Order, DemandForecast, BacklogItem, PurchaseOrder. Serialized as JSON.
6
Vue stores raw data in refs; computed properties derive the view
Raw lists like allOrders, inventoryItems live in ref(); tables/charts read from computed() that re-runs only when dependencies change.

Key Design Decisions

Stateless backend, no database

Data is loaded from JSON into Python lists at server startup. Every request filters those lists in-memory. Trade-off: simple to demo, easy to reset, but no persistence — restarts wipe any runtime change.

Filters are universal query params

Four shared filter dimensions (warehouse / category / status / month) flow through almost every endpoint. The Vue side keeps them in useFilters; the FastAPI side reuses one apply_filters() helper.

Raw refs + computed derivations

Components store API responses in plain ref(). Anything shown in the UI (totals, sorted tables, chart series) is a computed() — cached, recomputes only when inputs change. Keeps state minimal and reactivity predictable.

Pydantic as the contract

Every endpoint declares a response_model. JSON shape changes must update the model in lock-step — drift between data/*.json and Pydantic models is a known failure mode called out in CLAUDE.md.
